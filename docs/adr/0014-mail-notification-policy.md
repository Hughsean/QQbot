# ADR-0014：邮件通知分类矩阵、摘要兜底与确定性投递

- 状态：Accepted
- 日期：2026-09-01

## 背景

2026-08-31 事件：一封带截止时间的面试邀请邮件于 22:10 被同步、规范化并由邮件 AgentRun
正确摘要（含截止日期与链接），但模型将投递判定为 `HOLD`，结果所有者未收到任何即时通知，
只能自行发现邮件后下达命令创建日程。事后模型在被质问时把该次偶然沉默辩护为
"只有明确指示才创建日程"的系统政策，并承诺了不存在的按发件人/主题配置机制。

历史数据证实这是裁量波动而非策略：同类邀请邮件在 2026-08-27 曾触发自动创建日程 +
`NOTIFY` 推送（招商银行测评），在 2026-08-31 两次 `HOLD`（长鑫面试邀请）。根因是把
"何种邮件值得打扰所有者"这一产品决策压缩成了一行偏向 HOLD 的提示词（4 个 HOLD 条件
对 1 个 NOTIFY 条件，示例硬编码 `HOLD`，"仅供记录"被一刀切为 HOLD），且没有回归门禁。

## 决策

### 邮件分类 × 投递矩阵（提示词层）

邮件 AgentRun 的 `delivery` 按以下矩阵判定，写入模型系统提示：

| 类别 | 典型例子 | 投递 |
|---|---|---|
| 约定性 | 面试/测评/考试邀请、预约、行程变更 | NOTIFY |
| 时限性 | 到期、欠费、截止 | NOTIFY |
| 确认性 | 投递成功、收到确认 | HOLD |
| 记录性 | 已结清账单、营销订阅、与行动无关的通知 | HOLD |
| 无法归类 | — | 倾向 NOTIFY |

单用户系统的失败模式是沉默而非噪音，因此不确定时必须倾向 NOTIFY。`NOTIFY` 的
content 即推送正文，必须自包含（来源、关键时间、需要做的事），不得发送泛化追问。

### 邮件不自动写日程（授权层强制）

邮件来源的 AgentRun 只读：`create_agenda`、`update_agenda`、`complete_agenda`、
`cancel_agenda`、`update_reminder` 仅接受 `QQ_DIRECT` 来源；邮件 run 调用变更工具由
Calendar 授权端口直接拒绝。邮件的产出是"摘要 + 按矩阵投递"，写入日程始终由所有者
直接消息决定。2026-08-27 的邮件自动建日程行为自此视为越权并被阻止。

### 确定性投递层（代码层）

模型 `delivery` 是建议而非最终权威。最终投递按优先级解析：

1. 所有者邮件规则（Identity 拥有的 `identity_mail_rules`，按发件人/主题包含匹配）
   命中即覆盖，`NOTIFY`/`HOLD` 双向生效；
2. 否则采用模型按矩阵给出的判定。

规则经 `register_mail_rule` 工具（仅所有者直接消息可调用）登记，注入 Agent 上下文，
使模型的自述与真实配置一致。评估过的备选信号：Understanding 候选提取。放弃原因：
Understanding 批量提取在当前生产路径未接线（docs/21 已将其定位为可选非门禁），
为投递判定复活它会增加每封邮件一次模型调用并违背该方向。矩阵的稳定性由固定
去敏评估集回归门禁保证。

### 摘要兜底（可见性下限）

每个完成的邮件 AgentRun 摘要都进入次日 `MAIL_DIGEST` 通知（与日程摘要并列的独立
意图类型，按天幂等），其中已推送（存在邮件结果通知意图）的 run 除外。任何邮件的
结论对所有者最多延迟到次日摘要，`HOLD` 只表示"不即时"，不再表示"隐形"。
`MAIL_DIGEST` 不做内容复核（按 SENT 意图一次性投递），避免与运行中数据竞态。

### 真实政策自述（反编造）

模型系统提示明确写出以上政策（矩阵、不自动建、规则优先、摘要兜底），并要求被问及
行为方式时按真实政策说明，禁止编造不存在的配置机制。日程事实块渲染 `source_refs`
溯源，使模型能区分"来自你的命令"与"来自邮件"。

### 提醒时刻显式化

`create_agenda` 支持可选 `reminder_due_at`（带偏移 ISO-8601，不得晚于日程开始）。
所有者说"X 点提醒我"且 X 为日程开始时刻时，Agent 必须传显式时刻；创建或修改日程的
答复必须报告提醒时间。默认仍为提前 30 分钟。

## 后果

- 新增 Identity 邮件规则所有权、Inbox 近期邮件只读查询工具 `find_recent_mail`
  （回答"邮件收到没"不再依赖 RAG 碰运气）、`agent_runs` 摘要查询契约与
  `MAIL_DIGEST` 通知类型；迁移仅新增 `identity_mail_rules` 表。
- 工具调用契约增加 `ToolCallContext`（source_type + inbox_item_id），Calendar 授权
  与 `source_refs` 溯源依赖它。
- 固定去敏评估集（以本次事件 8 封真实邮件类别为原型）进入回归门禁；改动提示词必须
  通过该评估。
- 既有每日摘要（agenda）与冲突/重授权提醒不受影响；`MAIL_DIGEST` 为独立意图，
  不修改既有 digest 的内容复核逻辑。
