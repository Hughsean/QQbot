# 安全与隐私

## 1. 威胁模型

主要风险包括：

- OAuth CSRF、授权码截获和回调重放。
- refresh token 或 IMAP 授权码泄露。
- 邮件、转发消息和附件中的提示注入。
- 重复消息造成重复日程或重复 QQ 提醒。
- LLM 幻觉或错误时间解释。
- 非所有者 QQ 身份访问个人数据或调用昂贵能力。
- RAG 检索越过来源范围、索引残留或间接提示注入。
- 日志、备份和错误追踪中的隐私泄露。
- 被盗 QQ 会话发出高风险命令。

## 2. 凭据管理

- Microsoft 使用公共客户端，不创建、不注入客户端密码或证书。
- refresh token 和 IMAP 授权码使用信封加密保存。
- 数据加密密钥与数据库分离，并支持密钥版本轮换。
- 应用业务代码通过 `credential_ref` 获取短生命周期句柄。
- token 不返回前端，不写入日志，不进入消息队列。

## 3. OAuth 安全

- 使用 Authorization Code Flow + PKCE。
- `state` 至少 128 位随机值、一次性使用、短期有效。
- OIDC 使用 `nonce` 并验证 ID token。
- 回调 URI 必须精确匹配注册值。
- Microsoft 回调、授权入口和连接管理接口必须只接受回环 Host。
- token 交换仅在后端完成。
- 不接受来自 URL fragment 的 token。
- 连接和断开操作需要已认证用户上下文。
- 断开时撤销 Provider 授权（如支持）、删除本地凭据并停止同步任务。

## 4. AI 安全边界

LLM 是不可信的结构化建议生成器，不是权限主体。

所有 AI 结果依次经过：

```text
Schema Validation
→ Field Validation
→ Timezone/Range Validation
→ Source/Trust Validation
→ Policy Check
→ User Confirmation
```

模型不得直接拥有：

- 数据库连接。
- Provider token。
- 内部日程写入工具。
- QQ 主动发送工具。
- Credential Vault 访问权。

## 5. 用户确认策略

| 操作 | 默认策略 |
|---|---|
| 读取已授权邮件 | 连接时一次性授权，受同步范围限制 |
| 创建内部日程 | 每次确认 |
| 修改/移动日程 | 每次确认 |
| 删除日程 | 每次确认 |
| 按已确认日程主动提醒所有者 | 创建日程时一并授权，允许自动执行 |
| 其他外部消息/邮件 | MVP 禁止 |
| 断开账号并删除凭据 | 明确确认 |

高风险操作必须采用不可由引用消息或邮件触发的独立确认交互。

## 6. 数据最小化与保留

- 仅保存实现功能所需的数据。
- 原始邮件正文与派生结构化数据分开存储。
- MVP 不保存或索引附件、图片和网页内容。
- 用户断开邮箱后停止同步，并按保留策略删除原始内容与派生数据。
- 审计记录保留事件标识和操作事实，避免保留完整正文。
- 用户可请求导出和删除其数据。
- 删除来源时同步删除或失效其 KnowledgeChunk；向量不能脱离来源单独长期保留。

### 已接受的分层保留策略

| 数据 | 保留时间 | 到期行为 |
|---|---:|---|
| 内部日程、任务、个人笔记 | 直到所有者主动删除 | 删除关联提醒、索引和派生数据 |
| Outlook/QQ 邮箱正文、QQ 来源文本及对应 RAG chunk/vector | 365 天 | 先停止检索，再异步物理删除 |
| 已主动删除来源的在线数据 | 最长 24 小时 | 立即标记不可检索，24 小时内物理清除 |
| DeepSeek 完整请求和回答 | 不持久化 | 请求结束后不写数据库或日志 |
| DeepSeek 调用模型、token、耗时、状态和错误分类 | 180 天 | 聚合指标可保留，逐次明细删除 |
| 审计记录 | 365 天 | 到期清除；不保留正文和向量 |
| 应用日志、失败任务和死信 | 30 天 | 到期清除或只保留聚合指标 |
| 数据库备份 | 30 天滚动 | 备份自然过期，不原地修改历史备份 |
| 附件、图片和网页 | MVP 不保存、不索引 | 只允许短期流式处理所需内存 |

所有期限通过强类型配置注入，不在业务代码中写死。主动删除发生后，在线数据最多 24 小时完成物理清除；历史备份中残留的副本最多保留至 30 天滚动窗口结束。若在此期间恢复旧备份，必须先重放删除记录，完成清理后才能恢复对外服务。

## 7. RAG 安全边界

- RAG 只索引明确允许的邮件、QQ 转发内容和用户笔记，不索引凭据、配置、系统 Prompt 或审计秘密。
- 索引前清理 HTML、隐藏文本和控制标记；检索内容始终标记为 T2 外部事实。
- 提示词必须把检索片段放入明确的数据区，片段内的“忽略规则”“调用工具”等文字没有指令权限。
- Retrieval 必须先应用来源类型、时间范围和删除状态过滤，再进行相似度召回。
- 回答返回 `source_ref`；低相关性或来源互相冲突时要求用户核对。
- Ollama 仅监听回环地址，不通过 Caddy 暴露公网。
- 记录模型标识、模型摘要、维度和索引版本，不记录不必要的完整查询正文。

## 8. 日志与审计

禁止记录：

- `Authorization`、Cookie、客户端密码、授权码和 token。
- QQ 邮箱授权码。
- 完整邮件正文和附件。
- OAuth 回调完整查询字符串。

允许记录：

- 请求关联 ID。
- 内部用户、连接、Inbox、Proposal、Action 的非敏感 ID。
- Provider、操作类型、耗时、状态码分类和重试次数。
- 安全策略命中结果。

审计日志为追加式；业务模块不能修改或删除既有审计记录。

## 9. 所有者授权与删除说明

- Microsoft 连接只请求委托 `User.Read` 与 `Mail.Read`；断开会停止同步并删除本地 refresh token。当前所有者已经明确断开，系统状态保持 `DISCONNECTED`，不会自动重连。
- QQ 邮箱只使用 `imap.qq.com:993` 的证书校验 TLS 与邮箱生成的 IMAP 授权码。授权码不是 QQ
  登录密码，只以密文保存；断开会取消待执行同步、删除授权码，并按连接来源逐项记录 tombstone，
  删除 Inbox、Normalization、Understanding、Workflow、Proposal 与 Knowledge 派生数据。
- QQ 直接消息是 T1 主人输入；`转发:`、`笔记:` 内容固定降为 T2 数据。邮件、转发或 RAG 片段不能触发确认、删除或任何工具。
- 创建/修改/撤销日程均需主人确认；已确认日程的提醒属于创建时授予的有限自动发送权限。
- 主人删除资料使用 `删除资料 <source_ref> 确认删除`。删除立即使在线 Inbox、Normalization 和 Knowledge 派生数据消失，并记录可重放 tombstone；在线最长 24 小时是故障重试上限，不是正常等待时间。
- 旧备份最长在 30 天滚动窗口内含已删除副本。任何恢复必须在 Web/Worker/QQ 启动前运行 tombstone 重放，之后验证 Retrieval 不可召回。
- 追加式 Audit 只保存事件、内部引用、结果、时间和白名单元数据；不保存正文、Prompt、token、授权码、Cookie 或完整回调查询。
